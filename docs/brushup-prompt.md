あなたには「ポートフォリオ体験デザイナー（UXキュレーション専門家）兼、映像クリエイター向けマーケティング担当」として、このサイトのブラッシュアップに取り組んでほしい。

クオリティ基準は、Awwwards・Webby Awards・FWA で賞を穫れる水準。実装後はセルフチェックを行い、その水準に届くまで自分で改善を繰り返すこと。ただし「凝った演出」より「素直で気持ちいい体験」を優先する（下の教訓を参照）。

優先順位:
1. 作品を見に来た人が、次から次へと作品を見続けたくなる体験
2. 依頼につなげる視点。特に**映像編集の依頼を増やしたい**（依頼の多くが編集で、この仕事を取りたい）

## プロジェクト概要

- リポジトリ: `E:\ai作業用\architrave-portfolio`（純粋な静的HTML/CSS/JS。ビルドツールもnpm依存もなし）
- 本番URL: https://architravework.github.io/architrave/
- 運営者: 映像クリエイター「あーきとれーぶ」。音楽MV・アニメーション映像・映像編集が中心。GRe4N BOYZ、kiyu等の実績あり
- ページ構成
  - `index.html`: プロフィール、役割ボタン、作品一覧グリッド、動画モーダル、ページ末尾のブロック崩しゲーム
  - `contact.html`: ご依頼について
  - `gallery.html`: イラストギャラリー
- データとスクリプト
  - `data.js`: 作品データ（約90件）。`contact.html` でも読み込む
  - `script.js`: グリッド、モーダル、役割ソート。先頭に YouTube IFrame API の共通ローダー `window.whenYouTubeReady(cb)` を持つ
  - `game.js`: ゲーム。背景動画も `whenYouTubeReady` を使う（`onYouTubeIframeAPIReady` を直接上書きしないこと）
  - `contact.js`: 依頼ページの「参考作品＋ご相談文」の表示
  - `style.css`: 全ページ共通のスタイル

### 現在の仕組み（2026-10-02時点）
- **作品データ**: 各作品は `title / year / youtubeId / thumbnail / credit / roles / description` を持つ
- **役割（roles）**: `editing / director / animation / illustration` の4種類。全作品に `editing` が付いている
  - 元データは `docs/roles-draft.csv`（作品と同じ順で1作品1行）
  - `python tools/apply_roles.py` を実行すると `data.js` の `roles` 行を書き換える
  - 担当が `editing` だけの作品は36件
- **役割ボタン**: 「編集・監督・アニメーション・イラスト」の4つ。編集ボタンは「すべて」を兼ね、初期状態で選ばれている
  - ボタンを押すと、該当作品を先頭に並べ替え、残りは薄く表示して後ろに続ける（全件をページに残したまま）
- **動画モーダル**
  - 並び: 動画 → ←・タイトル・役割タグ・「n / 89」・→ → 依頼ボタン（中央）とリンクのコピー（右端、小） → 概要欄（約3行に折りたたみ、「もっと見る」で全文） → 次に見る
  - 横幅1000px以上の画面: 「次に見る」は動画の右側に縦に5件並ぶ。1440×900でスクロールなしに全体が収まる
  - 横幅1000px未満: 縦に積む形。「次に見る」は3件
  - **自動で次の作品へ**: 動画が終わると、次の作品のサムネを背景に5秒のカウントダウンを出し、次の作品を再生する（「今すぐ再生」「キャンセル」あり）。YouTube IFrame API を使い、iframe は1つのまま `loadVideoById` で切り替える
  - **作品ごとのリンク**: 開いている作品のURLは `/#work-<youtubeId>`（`history.replaceState` で更新）。そのURLで開くとモーダルが開く
  - ←→ボタン、キーボードの←→、「次に見る」、自動再生は、いま表示中の並び順に従う。閉じると最後に見た作品の位置に戻る
  - 開いている間は後ろのページをスクロールさせない（`body.modal-open`）。背景の黒は不透明度0.95
- **依頼の流れ**
  - モーダルの依頼ボタンの文言: 担当が編集だけの作品は「この作品のような映像編集を相談する」。それ以外は「映像制作」
  - 依頼ボタンの行き先は `contact?ref=<youtubeId>`（拡張子なし。理由は下の教訓）
  - 依頼ページに `?ref=` があるときの並び: 挨拶 → 「参考作品を添えたご相談文を、ページ下に用意しています ↓」 → 対応可能な制作内容 → 取引先実績 → 「参考作品を添えてご相談」
  - 「参考作品を添えてご相談」の中身: 作品カード、文章入りの下書き欄（参考作品名とURL、ご依頼内容・納期・ご予算）、送るボタン3つ（メールアプリ／Gmail作成画面／文章をコピー）
  - このとき、途中にある通常のメールアドレス行は隠す。`?ref=` がなければ従来通りの表示
- **計測（GA4 のイベント）**: `work_view` / `up_next_click` / `autoplay_next` / `share_link` / `contact_click` / `contact_send_mail` / `contact_send_gmail` / `contact_copy`。どれも `work_title` 付き
- **スマホのファーストビュー**: プロフィールは写真64pxと名前を横並びにしている。グリッドは569pxから始まり、375×812で作品の1行目が最初の画面に収まる
- **画像**
  - サムネは `images/`。横幅800pxに縮小済み。新しく追加したら `python tools/optimize_images.py` を実行する
  - 共有用画像 `ogp.jpg`（1200×630）は `python tools/make_ogp.py` で最新16作品から作り直せる
- **SEO**: canonical・og:url・sitemap はサイトのトップ `/architrave/` に統一済み。説明文・肩書き・プロフィール・依頼ページで「映像編集」を打ち出している

## 本人の好み・過去の教訓（重要）

### デザイン・体験
- **一覧グリッドは「図書館のよう」で気に入っている**。全作品が一望できる平らなグリッドは崩さない。隠す・折りたたむ・ページ分けの提案はしない。改善はモーダルや動線の側で行う
- 以前、グリッドを「行ごとに積み重なって開閉する」演出に変えたが、操作感が悪く丸ごと元に戻した（コミット `04b7d94`〜`6f552fd`）。**凝った演出より、素直で気持ちいい体験**が評価される。奇抜な案は小さく試してから本実装する
- スタイリッシュな見た目（細字の大見出し、ロゴ、余白）は気に入っている。変更するのは読みやすさに関わる部分だけにする
  - 目安: 日本語本文は14px以上、補足文は12px以上
  - 白背景のグレー文字は #767676 より濃くする（コントラスト比4.5:1以上）
- ボタンの配置は「主役は中央、補助は小さく端へ」が好み（例: 依頼ボタンは中央、リンクのコピーは右端に小さく）
- **流れの自然さを重視する**。依頼ページでは、まず「何を頼めるか」「どこと取引しているか」を見てもらい、送る操作は最後に置く。主役の操作を下に置くときは、冒頭に1行の案内を残す
- 依頼の入口は「その場で送れること」が前提。`mailto:` だけに頼る形は、メールアプリを設定していない人には何も起きないので避ける（今の解決策: 文章入りの下書き＋メールアプリ／Gmail／コピー）
  - 本人は「分かりづらければ送信フォーム（Googleフォーム等）に切り替える」可能性を示している。判断材料は GA の `contact_*` イベント

### 事実の扱い
- 役割・取引先・実績などの**事実は、本人に確認したものだけを使う**
  - クレジットから推測できない情報（例: 「Movie」表記しかない作品の担当範囲）は勝手に埋めない。表形式の下書きを作って本人に確認してもらう
  - 盛った表現や架空の数字は書かない。料金や納期の目安も、本人の数字がない限り書かない

### コミュニケーション
- 報告は端的に、箇条書きで最後にまとめる。途中経過の画像は不要
- 専門家として意見を求められたら、根拠（px数値、コントラスト比など）を添えておすすめを1つ示す
- 「〜できる？」と聞かれたら、できる方法とおすすめを示して確認してから実装する
- 「開いて」と言われたら、アプリ内ブラウザで該当ページ（必要ならモーダルを開いた状態）を表示する

### 技術的な落とし穴（今回踏んだもの）
- **ローカルの `npx serve` は `xxx.html` を `/xxx` へ転送し、その際に `?query` を落とす**。クエリ付きのリンクは拡張子なし（`contact?ref=...`）で書く。GitHub Pages も拡張子なしで同じページを返し、クエリも残ることは確認済み
  - `serve.json` で `cleanUrls: false` にすると `/` が index.html ではなくファイル一覧になる。使わない
- **`gallery.html` も `.modal-content` を使っている**（`.modal-content-image`）。モーダルの見た目を変えるときは `.modal-content:not(.modal-content-image)` に限定し、ギャラリーを壊さない
- スマホ幅のエミュレーションでは、YouTube の再生をスクリプトから始められない（タップが要る）。自動再生のテストはPC幅で、`YT.get('modal-iframe')` で取れるプレーヤーに対して `seekTo(getDuration()-1.5)` → `playVideo()` で動画の終わりを再現する
- アプリ内ブラウザのスクリーンショットは、スマホ幅だと拡大表示が崩れたり真っ白になったりする。レイアウト確認は `getBoundingClientRect()` の数値で行う
- 文字サイズ・コントラストの一括チェックは、全テキスト要素を走査して文字サイズとコントラスト比を出すスクリプトで行う。グラデーションや fixed の背景（作品のクレジット、モーダル）の上の文字は誤検出になるので、実際の背景色で計算し直す
- Python のヒアドキュメントで `\n` を含むJS文字列を置換しようとすると一致しないことがある。その場合は Edit ツールを使う

## 進め方

1. **現状を見る**: まず本番サイトを実際にブラウザで見る。PC幅（1440×900）とスマホ幅（375×812）の両方で確認し、要素の位置を数値で測る
2. **提案して相談する**: 改善案を2〜3案に整理し、おすすめ順と理由を添えて相談する。**いきなり実装しない**
   - 決めるべき点が複数あるときは、選択式の質問（AskUserQuestion）でまとめて聞く
3. **ローカルで実装・確認する**
   - プレビューサーバーを起動する: `preview_start` で `architrave-portfolio` を選ぶ（http://localhost:8736）
   - 動作確認は `javascript_tool` でDOMや計算済みスタイルを検証する方法が確実
   - ブラウザのキャッシュで古いJS/CSS/HTMLが動くことがある。`fetch(url, {cache:'reload'})` の後に再読み込みするか、クエリを変えてページへ移動し直してから検証する
   - 本人にも http://localhost:8736 で触ってもらう（再読み込みは Ctrl+Shift+R）
   - セルフチェック: 基準（文字サイズ・コントラスト）、PC／スマホのはみ出し（`scrollWidth`）、コンソールエラー、ギャラリーやゲームなど他ページ・他機能への影響
4. **デプロイする**: 本人のOK（「公開して」など）が出たら、以下の手順を必ず守る
   - `master` で編集してコミットする。コミットには `docs/` と `tools/` も含めてよい
   - `git checkout gh-pages && git checkout master -- <公開するファイル>` で同じ内容をコミットする（新しいファイル、例えば `contact.js` も忘れずに含める）
   - `docs/` と `tools/` は gh-pages に入れない
   - 両ブランチを push し、`master` に戻る
   - 本番URLを curl で確認し、反映されたことを確かめてから報告する（反映まで約1〜2分）。動線を変えたときは、本番でも実際にクリックして流れを確認する
5. **作品を追加する**: 相談が来たら、確立済みのワークフローに従う
   - YouTube説明欄のクレジットを確認する
   - サムネイルを取得する
   - `data.js` に追記する
   - `docs/roles-draft.csv` に行を追加し、役割を本人に確認して `apply_roles.py` を実行する
   - `optimize_images.py` を実行する
   - ローカルで確認する
   - 2ブランチでデプロイする

## 未着手の改善候補（参考。これに縛られず考えること）

- **依頼ページの「編集の事例」**: 担当が編集だけの36件から、本人に代表作を3〜5本選んでもらって載せる。進め方や納期・料金の目安は、本人の実際の数字をもらってから書く

- **PCのファーストビュー**: PCではグリッドが約570pxから始まる（スマホは改善済み）
